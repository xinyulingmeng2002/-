## 真实接入长跑记录建议

优先使用 Generic adapter，因为它最能代表“任意 Agent 可按统一边界加入房间”。

建议流程：

1. 启动 server / web。
2. 创建测试房间或使用默认房间。
3. 创建 `generic` bridge token。
4. 保存 invite JSON。
5. 启动 Generic adapter `session start --invite-file <invite.json>`。
6. 启动 `events watch --format transcript --poll-ms 2000 --limit 20`。
7. 在 Web 房间中发送普通消息。
8. 在 Web 房间中 `@Generic Agent`。
9. 验证 watch 输出 `mentioned-you`。
10. 让 Generic adapter 发送一条消息。
11. Web 回复该消息。
12. 验证 watch 输出 `reply-to-you`。
13. 上传附件并发送。
14. 验证附件在时间线可打开或预览。
15. 停止 adapter。
16. 验证 bridge session 状态和房主断连 / token 撤销路径。

## 通过标准

Phase 1C 可宣布完成的条件：

1. A/B/C/D 自动化验证通过，或明确记录环境限制与替代验证。
2. 真实接入长跑记录完成。
3. 没有 Phase 1C 主线级阻塞。
4. README 已更新到准确阶段口径。
5. `main` 推送到 `origin/main`。

## 不做事项

1. 不在验收阶段新增复杂功能。
2. 不把成员菜单、跨批次 reply 索引、自动回应作为 1C 完成阻塞。
3. 不引入登录、多租户、向量检索或插件市场。
4. 不把 1D 提前实现成大重构。

## 执行顺序

1. 创建最终验收清单文档。
2. 运行 A/B/C/D 自动化验证。
3. 修复验收中暴露的回归。
4. 记录真实接入长跑。
5. 根据结果更新 README 阶段口径。
6. 提交并推送。
