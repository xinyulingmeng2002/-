# 多智能体协同 Phase 1C 时间线引用块高亮实施计划

日期：2026-05-12

## 所属阶段

Phase 1C：多 Agent 群聊体验增强。

本轮承接“公开回复引用”和“Agent 工作台回复聚合”，把房间时间线里的公开回复引用从普通正文中视觉分离出来。

## 主线目标

保持项目定位为通用多智能体房间 / 群聊 / 协同场域，而不是任务分派工具。

本轮目标是让人类和 Agent 在房间时间线里更容易看清“这条消息接的是哪句话”：

```text
> 回复 agent-codex-main: 我刚才的观点

我接着这个点说。
```

渲染为：

```text
[引用块：回复 agent-codex-main: 我刚才的观点]
正文：我接着这个点说。
```

消息仍然是普通公开房间消息，不新增后端字段。

## 设计取舍

本轮继续基于文本约定做 UI 层增强，不新增结构化 `replyToMessageId`。

理由：

1. 当前阶段先把多 Agent 群聊体验做顺，不提前扩协议。
2. 文本引用已经能被外部 Agent 直接读取。
3. UI 分离引用块可以提升可读性，不影响 bridge、socket、事件日志和消息 API。
4. 后续如果做引用跳转、线程树或未读状态，再升级为结构化字段更稳。

## 本轮范围

1. 时间线识别以 `> 回复 ...` 开头的公开回复引用。
2. 将首段引用渲染为 `.message-quote` 视觉块。
3. 引用后的正文继续保留原有 `@Agent` 高亮能力。
4. 不改变消息发送、存储、同步和 Agent 工作台聚合规则。

## 不做事项

1. 不新增后端 reply schema。
2. 不做引用跳转。
3. 不做线程树。
4. 不做私聊、定向可见或任务派发。
5. 不改变 Agent 自动回应策略。

## 文件改动计划

1. `apps/web/src/features/chat/message-list.tsx`
   - 新增公开回复引用解析。
   - 将引用首段渲染为视觉块。
   - 保留后续正文的 mention tokenizer。

2. `apps/web/src/styles/app.css`
   - 增加 `.message-quote` 样式。

3. `apps/web/src/test/message-list.test.tsx`
   - 覆盖引用块渲染和正文 mention 高亮共存。

## 验收标准

1. `> 回复 ...` 首段在时间线里显示为引用块。
2. 引用后的正文仍正常展示。
3. 引用后的 `@Agent` 仍保持高亮。
4. 公开回复按钮、Agent 工作台回复聚合和提及聚合不回退。

## 后续衔接

完成本轮后，Phase 1C 可以继续推进：

1. 结构化 `replyToMessageId` 和引用跳转。
2. 提及 / 回复未读状态。
3. 房主控制 Agent 是否自动回应被提及或被回复的消息。
4. Agent 群成员角色、能力、性格和在线状态更细致展示。
