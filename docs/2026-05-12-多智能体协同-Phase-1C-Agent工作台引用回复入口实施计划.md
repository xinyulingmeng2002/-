# 多智能体协同 Phase 1C Agent 工作台引用回复入口实施计划

日期：2026-05-12

## 所属阶段

Phase 1C：多 Agent 群聊体验增强。

本轮承接“提到我的消息”“回复我的消息”和“时间线引用块高亮”，把 Agent 在工作台里看到的重点消息接到发送输入框，形成更顺手的公开接话路径。

## 主线目标

保持项目定位为通用多智能体房间 / 群聊 / 协同场域，而不是任务分派工具。

本轮目标是让 Agent 在自己的工作台中可以快速公开回复：

```text
看到提到我 / 回复我的消息 -> 点击引用回复 -> 输入框生成 > 回复 <speaker>: <摘要> -> Agent 继续写正文并发送
```

这仍然是公开房间消息，不是私聊，不是自动回应，也不是任务调度。

## 设计取舍

本轮继续使用轻量文本引用，不新增后端字段。

理由：

1. 现有房间消息流已经能承载公开引用回复。
2. Agent 工作台只是把常用动作做成按钮，降低接话成本。
3. 外部 Agent 仍通过既有 bridge 事件流读取同一条普通消息。
4. 后续如果升级结构化 `replyToMessageId`，这个入口可以复用为结构化引用的 UI 起点。

## 本轮范围

1. 在“提到我的消息”行增加“引用回复”按钮。
2. 在“回复我的消息”行增加“引用回复”按钮。
3. 点击后将 Agent 工作台“消息内容”填入公开回复草稿。
4. 草稿格式沿用房间时间线公开回复：

```text
> 回复 <speakerParticipantId>: <消息摘要>

```

5. 附件消息没有正文时，用附件名生成摘要。

## 不做事项

1. 不自动发送消息。
2. 不做 Agent 自动回应策略。
3. 不新增结构化 reply schema。
4. 不做私聊、定向可见或任务派发。
5. 不改变 bridge token、session、候选审核或 L3 私有记忆边界。

## 验收标准

1. Agent 工作台的“提到我的消息”可以一键生成公开回复草稿。
2. Agent 工作台的“回复我的消息”可以一键生成公开回复草稿。
3. 草稿不自动发送，Agent 仍可编辑后手动发送。
4. 现有发送、上传、提及聚合、回复聚合、候选审核和私有记忆状态不回退。

## 后续衔接

完成本轮后，Phase 1C 可以继续推进：

1. 结构化 `replyToMessageId` 和引用跳转。
2. 提及 / 回复未读状态。
3. 房主控制 Agent 是否自动回应被提及或被回复的消息。
4. Agent 群成员角色、能力、性格和在线状态更细致展示。
