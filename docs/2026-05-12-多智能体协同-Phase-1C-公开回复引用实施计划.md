# 多智能体协同 Phase 1C 公开回复引用实施计划

日期：2026-05-12

## 所属阶段

Phase 1C：多 Agent 群聊体验增强。

本轮承接“多 Agent 群聊成员可见性”“指名发言入口”“提及高亮与提到我的消息”，继续补齐群聊中最基础的自然对话能力：针对某条消息公开接话。

## 主线目标

保持项目定位为通用多智能体房间 / 群聊 / 协同场域，而不是任务分派工具。

本轮目标是让人类和 Agent 更容易在同一时间线里接续上下文：

```text
看到某条房间消息 -> 点击回复 -> 输入框生成短引用 -> 继续写公开消息 -> 仍作为普通 message.created 进入房间
```

这让多个 Agent 像群聊成员一样围绕同一个话题接话，不要求后端立即理解复杂 reply tree。

## 设计取舍

本轮采用轻量文本引用，不新增结构化 reply 字段。

理由：

1. 当前阶段优先增强群聊体验，不扩展协议更稳。
2. 引用文本能直接被外部 Agent 通过事件流读取。
3. 不改变消息持久化、socket 实时推送、bridge ingress/egress。
4. 后续如果需要线程、引用跳转、消息树或结构化上下文，可以在文本习惯稳定后升级协议。

## 本轮范围

1. 时间线聊天消息显示“回复”按钮。
2. 点击后把短引用写入主输入框。
3. 引用格式使用普通文本：

```text
> 回复 <speakerParticipantId>: <消息摘要>

```

4. 发送后仍走普通公开房间消息。
5. 附件消息没有正文时，用附件名生成引用摘要。

## 不做事项

1. 不新增后端 replyTo 字段。
2. 不做消息线程树。
3. 不做私聊、定向可见或任务分派。
4. 不做 Agent 自动回应。
5. 不改变 L3 私有记忆、候选审核或 bridge token 权限。

## 文件改动计划

1. `apps/web/src/features/chat/message-list.tsx`
   - 新增 `onReply` 回调。
   - 聊天消息渲染“回复”按钮。

2. `apps/web/src/features/chat/message-composer.tsx`
   - 新增 `draft` 输入。
   - 当外部 draft 变化时填入输入框。

3. `apps/web/src/features/rooms/room-shell.tsx`
   - 生成公开回复引用草稿。
   - 将回复行为从时间线接到 composer。

4. `apps/web/src/styles/app.css`
   - 新增回复按钮样式。

5. `apps/web/src/test/message-list.test.tsx`
   - 覆盖点击时间线回复按钮。

6. `apps/web/src/test/message-composer.test.tsx`
   - 覆盖 composer 接受回复草稿并发送。

7. `apps/web/src/test/room-shell.test.tsx`
   - 覆盖真实房间页从消息回复到发送的闭环。

## 验收标准

1. 用户能从任意聊天消息点击“回复”。
2. 输入框自动填入可读的公开引用文本。
3. 发送后的消息仍是普通房间消息，Agent 能通过既有事件流读取。
4. 指名发言、提及高亮、附件消息、候选审核和 Agent 面板不回退。

## 后续衔接

完成本轮后，Phase 1C 可以继续推进：

1. 引用消息在时间线里做视觉块高亮。
2. 结构化 `replyToMessageId`。
3. Agent 工作台聚合“回复我的消息”。
4. 房主控制 Agent 是否自动回应被提及或被回复的消息。
5. 更完整的 Agent 群成员角色与性格展示。
