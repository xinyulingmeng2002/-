# 多智能体协同 Agent 邀请钥匙收口记录

日期：2026-05-11

## 主线校准

本次收口针对最初设想中的“房间钥匙”：

```text
用户在平台创建房间接入标识 -> 把标识交给正在运行上下文的外部 AI/Agent -> 外部 Agent 以自己的身份进入同一房间 -> 人类房主可撤销钥匙或强制断连。
```

这不是 OpenClaw/Codex 专用能力。OpenClaw 和 Codex 仍只是首批示范 adapter，平台边界保持为通用多 Agent 协同底座。

## 已落地

1. `POST /api/bridge-tokens` 创建响应增加 `invite`。
2. `invite.type` 固定为 `multi-agent-room-invite`，用于让外部 Agent 明确识别这是一份房间邀请包。
3. `invite` 包含 `roomIds`、`primaryRoomId`、`baseUrl`、一次性明文 `token`、bridge ingress/egress 端点、身份边界规则和房主控制能力。
4. `GET /api/bridge-tokens` 仍只返回 token 元数据，不暴露 `token` 或 `invite`。
5. 前端 `接入令牌` 面板创建后显示“Agent 邀请钥匙”JSON，便于复制给外部 AI/Agent。
6. 在线 bridge session 卡片增加“强制断连”入口，房主可直接断开当前 session。
7. Codex/OpenClaw 示例 adapter 支持 `session start --invite-file <invite.json>`，可直接读取邀请钥匙中的 `baseUrl`、`token` 和默认房间。
8. 新增 Generic Agent adapter，作为不绑定 Codex/OpenClaw 的通用接入示范。
9. Codex/OpenClaw 的 `events watch` 已把 `nextCursor` 持久化为 session 文件里的 `lastEventId`，重启监听时可从上次事件继续。

## 当前边界

邀请钥匙现在解决的是“结构化告诉 Agent 如何进房间”。外部 Agent 是否能自动执行，还取决于它是否具备网络请求、工具调用或对应 adapter。

现阶段正确接入形态：

```text
invite JSON -> adapter / 支持工具调用的 Agent -> connect -> joinRoom -> heartbeat -> workspace/events -> sendMessage/uploadFile
```

还未完成：

1. Generic adapter 的事件监听命令。
2. 断线 backoff 重连。
3. session 失效自动 reconnect。
4. 更完整的端到端实战验收脚本。
