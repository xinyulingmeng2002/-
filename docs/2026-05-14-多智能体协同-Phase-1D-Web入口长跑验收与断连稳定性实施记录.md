# Phase 1D Web 入口长跑验收与断连稳定性实施记录

## 结论

本轮完成一次更接近真实使用的 Phase 1D 验收：使用真实 dev server、真实 Vite Web 入口、真实 Generic adapter CLI，通过前端 `/api` 代理完成外部 Agent 入房、监听、主动发言、提及/回复、附件消息和 bridge session 可观测性检查。

验收中发现并修复一个稳定性问题：外部执行 `session stop` 删除 session 文件后，长运行的 `session start` 进程会在下一次 heartbeat 读取 session 文件时因 `ENOENT` 崩溃。修复后 Generic CLI 能感知外部 stop 并平滑退出；Codex/OpenClaw adapter 也同步增加了 heartbeat 文件缺失防护。

## 发现的问题

外部执行：

```bash
npm --workspace @ma/bridge-generic run dev -- session stop --session-file /tmp/ma-phase1d-browser-run-data/generic-session.json
```

原 `session start` 长进程会在下一次 heartbeat 报：

```text
ENOENT: no such file or directory, open '/tmp/ma-phase1d-browser-run-data/generic-session.json'
```

根因：

- `session stop` 会删除 session 文件。
- `runGenericBridgeSession` 的 heartbeat interval 每次从 session 文件读取 cursor/diagnostics。
- 文件缺失未被识别为外部 stop 信号。

## 修复

- Generic runtime 在 heartbeat tick 遇到 session 文件缺失时：
  - 停止 heartbeat interval。
  - 触发 `onSessionFileMissing`。
  - 不再发送 heartbeat。
- Generic/Codex/OpenClaw CLI 的 `session start` 同时等待：
  - 用户 `SIGINT/SIGTERM`。
  - runtime 的外部 stop 信号。
- 三套 adapter 在外部 `session stop` 删除 session 文件后，都应停止 heartbeat 并让长进程平滑退出或等待正常信号收束，不再因 `ENOENT` 崩溃。
