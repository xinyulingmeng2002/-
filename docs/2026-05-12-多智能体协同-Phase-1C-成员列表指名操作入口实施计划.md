# 多智能体协同 Phase 1C 成员列表指名操作入口实施计划

日期：2026-05-12

## 所属阶段

Phase 1C：多 Agent 群聊体验增强。

本轮承接“主输入框指名发言”和“Agent 工作台指名发言入口”，把右侧参与者列表从纯展示名单推进为群聊成员操作入口。

## 主线目标

本项目的房间是群聊房间。真人和 Agent 都是房间成员，不应只作为被管理对象或任务执行对象出现。

本轮目标是让房主在成员列表里看到任意成员后，可以直接从成员卡片发起公开指名发言：

```text
看到成员 -> 点击“对 TA 说” -> 主输入框生成 @<displayName> -> 房主编辑正文并发送到公开房间
```

这仍然是公开群聊消息，不是私聊，不是任务派发，也不是强制 Agent 回应。

## 设计取舍

本轮做轻量成员卡操作，不引入复杂菜单。

理由：

1. 当前阶段更需要补齐群聊基本动作，而不是过早做复杂成员治理。
2. 参与者列表已经是房主查看成员的自然位置。
3. `@displayName` 文本提及已经被主输入框、时间线高亮和 Agent 工作台识别。
4. 后续可以把同一个操作区域扩展为成员菜单，加入查看资料、打开 Agent 工作台、断连、禁言等治理能力。

## 本轮范围

1. `ParticipantList` 支持可选的成员指名回调。
2. 每个成员卡片在有回调时显示“对 TA 说”操作。
3. 点击操作后，主输入框填入 `@<displayName> `。
4. 人类成员和 Agent 成员都走同一个操作模型。

## 不做事项

1. 不做私聊或定向可见。
2. 不做自动回应。
3. 不做任务派发。
4. 不做成员详情弹窗。
5. 不做新的后端协议或结构化 mention schema。

## 验收标准

1. 成员列表里的 Agent 成员可以被直接指名。
2. 成员列表里的真人成员也使用同一操作模型。
3. 点击后只生成草稿，不自动发送。
4. 现有主输入框指名发言、公开回复、Agent 工作台、桥接会话和候选审核不回退。

## 后续衔接

完成本轮后，Phase 1C 可以继续推进：

1. 成员卡扩展为统一成员操作菜单。
2. 成员在线 / 离线 / 未接入状态在统一列表内展示。
3. Agent 工作台、断连、token 撤销等治理动作和群聊动作分层呈现。
4. 后续结构化 mention / reply 统一接入同一成员操作入口。
