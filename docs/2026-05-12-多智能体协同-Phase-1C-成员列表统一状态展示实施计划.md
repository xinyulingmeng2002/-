# 多智能体协同 Phase 1C 成员列表统一状态展示实施计划

日期：2026-05-12

## 所属阶段

Phase 1C：多 Agent 群聊体验增强。

本轮承接“成员列表指名操作入口”，继续把右侧参与者列表从名单推进为房间成员的统一入口。

## 主线目标

本项目的房间是群聊房间。真人和 Agent 都是房间成员，用户应能在同一个成员列表里理解每个成员当前是否可达，而不是在成员列表、桥接会话和 token 面板之间反复对照。

本轮目标是在成员卡片里直接展示统一状态：

```text
成员状态：在线
成员状态：离线
成员状态：未接入
```

这只是成员可达性展示，不改变权限模型，不强制 Agent 回应，也不引入任务派发。

## 状态定义

1. 在线
   - 当前真人自己在线。
   - 实时 presence 出现的成员在线。
   - Agent 有 connected bridge session 且 session 绑定当前房间。

2. 离线
   - Agent 有 bridge session 记录且绑定当前房间，但 session 已 disconnected。

3. 未接入
   - 房间成员存在，但当前没有可用 bridge session 或实时 presence。
   - Observer 这类默认系统观察者在没有 session 时显示为未接入。

## 设计取舍

本轮只在前端聚合已有数据，不新增后端字段。

理由：

1. 房间成员、实时 presence 和 bridge session 数据已经足够支撑第一版状态。
2. 状态显示是群聊基础体验，不应等待复杂治理模型完成。
3. 后续如果后端提供更精确的 presence state，可以替换当前前端推导逻辑。

## 本轮范围

1. `ParticipantViewModel` 增加成员状态字段。
2. `RoomShell` 根据 realtime participants、bridge sessions 和当前说话者推导状态。
3. `ParticipantList` 在每张成员卡里显示成员状态。
4. 测试覆盖在线 Agent、离线 Agent 和未接入 Observer。

## 不做事项

1. 不做自动重连控制。
2. 不做强制断连入口迁移。
3. 不做成员详情弹窗。
4. 不做后端 presence schema 改造。
5. 不做私聊、定向可见或任务派发。

## 文件改动计划

1. `apps/web/src/features/participants/participant-list.tsx`
   - 扩展成员视图模型。
   - 渲染状态文本。

2. `apps/web/src/features/rooms/room-shell.tsx`
   - 增加成员状态推导函数。
   - 把状态写入参与者列表视图模型。

3. `apps/web/src/styles/app.css`
   - 增加成员状态视觉样式。

4. `apps/web/src/test/room-shell.test.tsx`
   - 覆盖在线、离线、未接入三种状态。

## 验收标准

1. 成员列表能显示在线成员。
2. 成员列表能显示离线 Agent。
3. 成员列表能显示未接入成员。
4. 成员指名发言、主输入框、桥接会话、Agent 工作台和候选审核不回退。

## 后续衔接

完成本轮后，Phase 1C 可以继续推进：

1. 成员卡统一操作菜单。
2. Agent 工作台打开、断连、token 撤销等治理动作分层展示。
3. 更细的心跳时间、TTL 和最近错误提示。
4. 后端提供正式 presence state 后替换前端推导。
