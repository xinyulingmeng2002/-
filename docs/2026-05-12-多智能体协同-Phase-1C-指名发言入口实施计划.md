# 多智能体协同 Phase 1C 指名发言入口实施计划

日期：2026-05-12

## 所属阶段

Phase 1C：多 Agent 群聊体验增强。

本轮紧接“多 Agent 群聊成员可见性”，从“看见房间里有哪些 Agent”推进到“可以自然点名和某个 Agent 说话”。

## 主线目标

保持项目定位为通用多智能体房间 / 群聊 / 协同场域，而不是任务分派工具。

本轮目标是增强人类房主和 Agent 群成员之间的自然聊天入口：

```text
房间成员可见 -> 点击某个 Agent -> 消息自动带上 @称呼 -> 进入普通房间消息流
```

## 设计取舍

本轮采用轻量自然语言点名，不新增结构化 mention 协议。

理由：

1. 当前主线优先是群聊体验，不是复杂路由。
2. `@显示名` 能直接被所有 Agent 在房间事件流里读到。
3. 不需要修改服务端消息协议、bridge ingress/egress 或事件日志结构。
4. 后续如果要做通知、唤醒、定向派发，可以在已有文本点名习惯上升级为结构化字段。

## 本轮范围

1. `MessageComposer` 支持 `mentionTargets`。
2. 每个目标渲染为 `对 <displayName> 说` 按钮。
3. 点击后把 `@<displayName> ` 插入消息开头。
4. `RoomShell` 从当前参与者列表中提取 Agent，传给 composer。
5. 保持发送链路仍为普通 `message.created`，不改变后端协议。

## 不做事项

1. 不做结构化 mentions 字段。
2. 不做 Agent 自动回复或自动唤醒。
3. 不做消息路由或私聊。
4. 不做权限系统变化。
5. 不把任务分派作为本轮主题。

## 文件改动计划

1. `apps/web/src/features/chat/message-composer.tsx`
   - 新增 `MessageComposerMentionTarget`。
   - 新增 `mentionTargets` props。
   - 新增点名按钮和插入逻辑。

2. `apps/web/src/features/rooms/room-shell.tsx`
   - 从房间参与者中过滤 Agent 作为点名目标。
   - 排除 `system`。

3. `apps/web/src/styles/app.css`
   - 为点名按钮和点名区域补样式。

4. `apps/web/src/test/message-composer.test.tsx`
   - 覆盖点击点名按钮后发送 `@Agent` 前缀。

5. `apps/web/src/test/room-shell.test.tsx`
   - 覆盖真实房间页中已接入 Agent 会出现在点名入口里。

## 验收标准

1. 人类用户能在房间输入区看到可点名的 Agent。
2. 点击 `对 X 说` 后，消息正文带 `@X`。
3. 发送仍走普通房间消息流，不破坏附件、摘要、候选审核等既有能力。
4. 外部 Agent 通过 bridge events/workspace 能读到这条普通消息。

## 后续衔接

后续可以继续推进：

1. 时间线高亮 `@Agent`。
2. Agent 工作台筛选“提到我的消息”。
3. 结构化 mention schema。
4. 房主控制 Agent 是否自动回应被点名消息。
5. Agent 之间互相回复引用。
