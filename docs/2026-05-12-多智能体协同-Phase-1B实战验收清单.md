# 多智能体协同 Phase 1B 实战验收清单

日期：2026-05-12

## 验收目标

验证“房间钥匙”主线已经形成可重复运行的最小实战闭环：

```text
创建 Agent 邀请钥匙 -> Agent 入房 -> 拉取事件 -> 获取工作快照 -> 发送带附件消息 -> 私有记忆提交共享候选 -> 人工接受 -> 房主强制断连
```

这条验收不绑定 Codex/OpenClaw。当前 smoke 用 `generic` bridge 类型验证统一边界，Codex/OpenClaw adapter 仍走同一协议能力。

## 一键验收命令

```bash
npm run smoke:phase1b
npm run smoke:phase1b:cli
```

底层测试文件：

```text
apps/server/test/phase-1b-smoke.test.ts
scripts/phase1b-generic-cli-smoke.ts
```

## 已覆盖能力

1. `POST /api/bridge-tokens` 创建 `multi-agent-room-invite`。
2. Agent 使用 token 调用 `connect` 并获得 `session.id`。
3. Agent 调用 `join-room` 绑定目标房间。
4. 人类消息进入房间时间线。
5. Agent 通过 bridge egress `events` 拉取房间事件。
6. Agent 通过 bridge egress `workspace` 获取房间工作快照。
7. 附件通过 `/api/uploads` 上传并得到 canonical attachment metadata。
8. Agent 通过 bridge ingress `message` 发送带附件消息。
9. Agent 私有记忆通过受控接口提交为共享候选。
10. 人工审核接受候选，内容进入共享知识。
11. 房主通过 `/api/bridge-sessions/:id/disconnect` 强制断开 session。

## 边界说明

本 smoke 是无浏览器、无外部网络、无真实 CLI 常驻进程的服务端集成验收。它验证协议和服务端闭环是否成立，不替代后续真实 adapter 进程长时间运行验收。

`smoke:phase1b:cli` 会启动临时本地 HTTP 服务，并通过真实 Generic bridge CLI 命令验证：

1. `session start --invite-file <invite.json>` 可以读取房间邀请钥匙并保持 session。
2. `message send` 可以通过持久化 session 文件发言。
3. `workspace snapshot` 可以读取房间工作快照。
4. `events pull` 可以拉取房间事件。
5. 脚本结束时会向 `session start` 进程发送 `SIGINT`，触发 adapter 清理。

该命令需要当前环境允许监听 `127.0.0.1`。在受限沙箱中运行时，可能需要提升权限。

真实长运行 adapter 的能力已经分别由 Codex/OpenClaw/Generic runtime 测试覆盖：

1. `events watch` cursor 持久化到 `lastEventId`。
2. 短暂拉取失败时指数 backoff 重试。
3. 明确 session 失效时自动 `connect -> joinRoom` 并继续使用原 cursor 监听。

## 当前结论

Phase 1B 已具备“初步拿来实战试用”的最小闭环：

1. 用户可以创建房间邀请钥匙。
2. 外部 Agent 可以按统一协议进入房间。
3. Agent 可以读取房间上下文、发送消息和附件。
4. 私有记忆进入共享层仍需要人工审核。
5. 房主可以强制断开在线 bridge session。

后续重点应从“打通链路”转向“真实进程体验”和“长期运行可观测性”，例如 CLI 实跑脚本、健康面板、日志、失败告警和更明确的 adapter 运维入口。
