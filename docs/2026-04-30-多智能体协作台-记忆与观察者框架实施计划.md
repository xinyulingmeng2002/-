# 记忆与观察者框架 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 `L0/L1 + Observer` 骨架上，补齐共享候选层、`L2` 轻量共享知识层、`L3` 最小可用私有记忆层，以及相应的人工确认链路。

**Architecture:** 保持 `apps/server` 为事实中心。所有消息与附件继续先写 `L1` 事件日志，再通过独立的 `MemoryPipelineService` 投影到 `L0`，并触发 `Observer` 生成共享候选与私有沉淀。共享候选接受后才允许更新 `L0` 或写入 `L2`，`L3` 只能由所属 Agent 读写并通过候选机制共享。

**Tech Stack:** Node.js 22, npm workspaces, TypeScript, Fastify, React, Vite, Vitest, Testing Library, Zod, JSON file storage

## Scope Decision

本计划只覆盖“框架第一轮落地”，不追求完整产品形态。

进入本计划：

1. 统一事件对象扩展
2. 共享候选存储与审核 API
3. `L2` 轻量共享知识存储与查询 API
4. `L3` 私有记忆存储、查询、提交共享候选 API
5. `MemoryPipelineService` 与 `ObserverService` 的职责重整
6. 最小验证用例

不进入本计划：

1. embedding / vector search
2. 自动审核或自动上浮私有记忆
3. 完整 Web 后台界面
4. 数据库迁移
5. 跨房间关系图谱

## Implementation Notes

1. 不能继续让 `MessageService` 同时维护越来越多的记忆规则，必须引入 `MemoryPipelineService`
2. `ObserverService` 负责“分析并生成建议”，不负责最终裁决
3. 候选接受 / 拒绝必须写回事件日志，保证可追踪
4. `PrivateMemoryStore` 必须按 `agentId` 做命名空间过滤
5. 文件型持久化仍用 `writeJsonSnapshotAtomic`
6. 所有测试都必须验证“先写事实，再做派生”的顺序性
