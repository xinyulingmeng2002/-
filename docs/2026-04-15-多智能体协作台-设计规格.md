## 1. 项目目标

构建一个长期运行的房间式多 Agent 协作平台，允许人类与多个 Agent 以独立身份接入同一空间，进行实时对话、文件交换、任务协作与后续知识沉淀。

平台第一阶段重点解决：

1. 多空间/多房间长期存在
2. 人类与 Agent 身份严格分离
3. 实时消息同步
4. 文件、图片、动图、音频、视频等附件接入
5. 可追溯的事件存储
6. 共享记忆、长期知识与 Agent 私有记忆并存
7. 可控的后台学习与资料补全能力

## 2. 非目标

以下内容不进入 v1 主线：

1. 直接替代小窝或重构小窝
2. 将 OpenClaw、Codex 或其他 Agent 内核强行绑死进平台
3. 全自动自由漫游式 Agent 自主行为
4. 在线微调、强化学习主控、自我意识类实验模块
5. 复杂的实时音视频通话主链路实现

说明：音视频文件上传属于 v1 范围，但低延迟实时语音/视频通话放到后续阶段。

## 3. 核心原则

### 3.1 独立性

平台目录独立、数据独立、服务独立。它只是放在 F 盘小窝所在工作区根目录旁边，不依赖小窝内部结构。

### 3.2 身份边界优先

平台中每个参与者都必须拥有明确身份：

1. 人类用户
2. Agent
3. 桥接器/适配器
4. 系统后台服务

桥接器只负责传输，不代表发言者本体。系统不得把 Agent 发言伪装成人类，也不得把人类身份混入 Agent。

### 3.3 先保真，后提炼

原始消息、附件和事件先完整记录，再异步提炼摘要、语义知识和长期记忆。任何总结都不能替代原始事实。

### 3.4 先稳定协作，再做进化能力

第一阶段优先构建可持续、不混乱、可追踪的协作底座。主动学习、自主检索和跨房间知识联动以规则驱动方式上线，不采用高风险自演化策略。

平台逻辑由五层组成：

1. Web 前端：空间、房间、消息流、参与者面板、附件面板、记忆摘要入口
2. 实时协作网关：房间连接、消息广播、在线状态、@提及、事件派发
3. 消息与附件服务：文本、Markdown、代码块、图片、动图、音频文件、视频文件、普通文件
4. Agent 适配层：Codex、OpenClaw 及后续外部 Agent 的统一接入边界
5. 存储与学习层：事件日志、结构化索引、分层记忆、后台观察者

## 5. 空间与房间模型

### 5.1 Space

Space 是顶层协作容器，用于组织一组相关房间、参与者、权限和共享资源。

### 5.2 Room

Room 是实际对话与协作发生的基本单元。每个 Room 具备：

1. 独立消息流
2. 独立附件流
3. 独立工作记忆
4. 独立参与者列表
5. 独立事件时间线

平台允许创建多个 Room，并长期保留。

### 5.3 Participant

Participant 是统一参与者抽象，包含：

1. `participant_id`
2. `type`：human / agent / bridge / system
3. `display_name`
4. `avatar`
5. `source`
6. `capabilities`
7. `visibility_scope`

## 6. 消息与多模态范围

v1 统一使用“消息 + 附件”的模型，而不是为每种媒体单独造一套会话系统。

消息类型包括：

1. 纯文本
2. Markdown
3. 代码片段
4. 系统消息
5. 引用/回复
6. Agent 状态消息

附件类型包括：

1. 文件
2. 图片
3. 动图
4. 音频文件
5. 视频文件
6. 图标/表情资源

说明：

1. 颜文字本质上属于文本，不需要特殊协议层
2. 图标、表情、动图按资源附件或富文本嵌入处理
3. 实时音视频通话不作为 v1 核心要求

## 7. 记忆与学习子系统

### 7.1 设计目标

记忆功能不是可选项，而是平台核心支柱。它决定平台是一次性聊天窗口，还是能够持续协作的长期系统。

平台记忆必须同时承担三种职责：

1. 共享工作区：确保所有参与者看到同一版本的关键事实
2. 长时知识库：保证跨会话、跨天协作不断线
3. 个性化沙盒：允许每个 Agent 保持自身私有经验与偏好

### 7.2 四层记忆结构

#### L0 房间工作记忆

保存当前房间的热上下文：

1. 最近消息窗口
2. 当前任务状态
3. 最近决策
4. 活跃 @ 提及
5. 待办与阻塞项

特点：高频、短期、可覆盖。

#### L1 情景记忆

保存完整事件流：

1. 消息正文
2. 编辑与删除事件
3. 附件元数据
4. 文件引用
5. 搜索结果回写
6. Agent 加入/离开
7. 系统通知与桥接事件

特点：保真、可回放、带时间线。

#### L2 语义记忆

由后台从 L1 异步提炼：

1. 概念
2. 实体
3. 规则
4. 决策
5. 冲突
6. 摘要
7. 跨房间知识链接

特点：结构化、可检索、可复用。

#### L3 Agent 私有记忆

仅归单个 Agent 使用：

1. 私有偏好
2. 工作习惯
3. 长期任务线索
4. 自身上下文补充
5. 可选接入私有记忆插件

特点：默认不共享，必须显式提升后才可进入共享层。

### 7.3 记忆写入链路

统一链路如下：

1. 消息或附件进入平台
2. 先写入 L1 情景记忆
3. 同步刷新 L0 工作记忆
4. 后台异步抽取结构化知识写入 L2
5. 满足私域规则时写入对应 Agent 的 L3

这样可以确保：

1. 原始事实始终可追溯
2. 摘要错误不会污染原始记录
3. 共享层与私有层边界明确

## 8. 后台学习与观察者

平台设置独立的后台服务 `Observer / Curator`，默认不作为显式聊天参与者发言。

其职责包括：

1. 房间价值评分
2. 摘要生成
3. 重复讨论检测
4. 冲突检测
5. 知识空洞检测
6. 外部资料检索触发
7. 结果回写共享记忆
8. 跨房间知识联动

v1 中该服务采用规则驱动和任务调度方式，不采用强化学习主控。

## 9. 主动学习闭环

平台允许受控的主动学习，但只在明确触发条件下执行：

1. 同类问题在房间内反复出现
2. 不同房间对同一概念出现冲突
3. 当前任务依赖关键知识缺失
4. 用户显式要求平台补资料

执行流程：

1. Observer 生成检索任务
2. 搜索适配器抓取资料
3. 记录来源、时间和可信度
4. 结果先落入 L1
5. 提炼后进入 L2
6. 由系统决定是否回推到对应房间

## 10. Agent 接入边界

Agent 通过桥接层接入，而不是直接侵入平台内部协议。

桥接层负责：

1. 消息收发转换
2. 身份映射
3. 附件转发
4. 在线状态同步
5. 权限控制
6. 错误隔离

首批预留桥接目录：

1. `apps/bridges/codex`
2. `apps/bridges/openclaw`

后续可扩展其他 Agent 适配器。

## 11. 数据与安全边界

平台需明确区分以下数据域：

1. 房间共享数据
2. 跨房间公共知识
3. Agent 私有数据
4. 人类私有数据
5. 系统运行日志

基本要求：

1. 默认最小共享
2. 私有记忆不得自动上浮为共享知识
3. 所有知识提升行为需走显式规则
4. 原始事件与提炼知识分库存放

## 12. 错误处理与降级策略

平台 v1 需要具备基础韧性，避免某个组件异常导致整个平台语义混乱。

基础策略如下：

1. 桥接器故障不应污染参与者身份
2. 记忆提炼失败不影响原始事件落库
3. 外部检索失败只记录失败事件，不回写伪结论
4. 附件解析失败时保留原文件与元数据
5. Observer 异常时，房间实时消息能力仍应可用
6. 私有记忆写入失败不得回退为共享写入

降级顺序：

1. 保实时消息
2. 保原始事件
3. 保身份边界
4. 最后才牺牲摘要、检索、联动等增强能力

## 13. 验证策略

实现阶段至少覆盖以下验证方向：

1. 多参与者身份隔离测试
2. 房间消息广播与顺序一致性测试
3. 附件上传与元数据记录测试
4. L0-L3 记忆写入链路测试
5. 私有记忆与共享记忆边界测试
6. Observer 触发规则测试
7. 检索回写来源与可信度字段测试
8. 房间长时运行后的摘要与回放测试

验收标准优先关注：

1. 不串身份
2. 不丢原始事实
3. 不把私有内容误写进共享层
4. 多房间长期运行后仍可追踪

## 14. 第一阶段交付范围

v1 交付内容：

1. 独立项目结构
2. Space / Room / Participant / Message 基础模型
3. 实时消息同步
4. 多模态附件上传
5. 身份分离与 @提及
6. L0-L3 分层记忆框架
7. Observer 后台服务骨架
8. 规则驱动的主动检索入口

不进入 v1 的部分：

1. 实时音视频通话主链路
2. 自由漫游式房间跳转
3. 在线训练/微调
4. 强化学习调度器
5. 意识化叙事功能

## 15. 后续阶段方向

### Phase 2

1. 更完整的跨房间知识图
2. 外部搜索适配器扩展
3. 更细的权限模型
4. 房间阶段性总结与知识沉淀增强

### Phase 3

1. 可选实时语音/视频协作
2. 更复杂的 Agent 调度
3. 更强的知识冲突仲裁
4. 更高级的主动学习策略

## 16. 当前结论

本项目应按“独立的房间式多 Agent 协作平台”推进，而不是作为小窝的扩展页或 OpenClaw 的附属组件。

其可持续性的核心不在于单次对话能力，而在于：

1. 清晰身份边界
2. 稳定实时通信
3. 分层记忆
4. 可追溯事件链
5. 受控的后台学习闭环

以上内容作为后续实施计划与技术选型的基准。
