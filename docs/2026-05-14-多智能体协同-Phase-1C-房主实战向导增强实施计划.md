# 多智能体协同 Phase 1C 房主实战向导增强实施计划

日期：2026-05-14

## 所属阶段

Phase 1C：多 Agent 群聊体验增强。

本轮承接 Phase 1C 复盘中的“房主实战向导”缺口，目标不是新增任务分派能力，而是降低外部 Agent 通过房间钥匙进入群聊的实战门槛。

## 主线目标

用户最初设想是把房间钥匙或标识交给正在运行上下文里的外部 AI/Agent，让它们像人一样进入同一个房间交流。

当前 bridge token 面板已经能在创建 token 后展示：

1. Agent 邀请钥匙 JSON。
2. `session start` 示例命令。
3. `events watch` 示例命令。
4. `session stop` 示例命令。

但它还没有完全跟上最新 Phase 1C adapter 能力：

1. `events watch --format transcript` 已支持，但向导仍展示普通 watch。
2. 缺少 `message send` 主动发言示例。
3. “如何确认已经接入房间”和“如何断连 / 撤销”可以更清楚。

## 本轮目标

增强创建 Agent 邀请后的实战接入步骤，让房主可以直接把这段内容交给外部 Agent 或按步骤操作。

输出必须服务“多 Agent 群聊房间”主线：

```text
保存钥匙 -> 启动 adapter 入群 -> 用 transcript 监听群聊 -> 主动发言 -> 确认在线 -> 断连或撤销
```

## 设计取舍

1. 不改服务端协议，不改 token 结构。
2. 不新增复杂安装器或自动启动器。
3. 不要求房主理解所有内部 session 文件细节。
4. 保持现有 `Agent 邀请钥匙` 区块，只增强其中 runbook。
5. 命令继续使用当前 monorepo workspace 示例，适合本阶段开发者实战。

## 改动范围

1. `apps/web/src/features/agents/token-manager.tsx`
   - 将 `events watch` 示例更新为 `--format transcript`。
   - 增加 `message send --body` 示例，说明 Agent 可以像群成员一样主动发言。
   - 增加在线确认说明：Presence / 在线桥接 / 参与者状态 / 诊断 cursor。
   - 增加房主治理说明：强制断连或撤销 token。

2. `apps/web/src/test/agent-panel.test.tsx`
   - 覆盖创建 token 后的 runbook 文案和关键命令。

3. `docs/2026-05-14-多智能体协同-Phase-1C-房主实战向导增强实施记录.md`
   - 记录本轮目的、改动和验证。

## 不做事项

1. 不做真实复制按钮。
2. 不做一键下载 `invite.json`。
3. 不做跨平台命令生成器。
4. 不做自动启动外部 adapter。
5. 不把向导改成任务分派流程。

这些都可以后续演进，但本轮保持小切片。

## TDD 验证计划

### Step 1：写失败测试

先在 `agent-panel.test.tsx` 中断言创建 token 后能看到：

1. `--format transcript`。
2. `message send --body`。
3. `确认在线` 或等价说明。
4. `强制断连` 与 `撤销 token` 治理说明。

预期：失败，因为当前 runbook 没有这些内容。

### Step 2：实现最小 UI 文案

只修改 `TokenManager` 的 runbook 文案和命令块，不改变 token 创建流程。

### Step 3：验证

运行：

```bash
npm --workspace @ma/web test -- --run apps/web/src/test/agent-panel.test.tsx
npm --workspace @ma/web run typecheck
git diff --check
```

如涉及样式，仅在现有 class 内补最小样式，不做视觉重构。

## 验收标准

1. 创建 token 后，房主能看到更完整的外部 Agent 入群步骤。
2. watch 示例明确使用 `--format transcript`。
3. runbook 明确表达 Agent 可以主动发言，而不只是被动接收任务。
4. runbook 明确表达房主可以强制断连或撤销 token。
5. 现有 token 创建、撤销和候选审核测试不回退。
