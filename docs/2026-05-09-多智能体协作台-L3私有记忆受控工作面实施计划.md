# 多智能体协作台 L3 私有记忆受控工作面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不暴露 `L3` 私有记忆原文到普通公共面板的前提下，为指定 Agent 提供最小可用的私有记忆工作面，并为人类提供去敏状态感知与受控提交链路。

**Architecture:** 继续保持 `L1 -> 派生层 -> L0/L2/L3` 的主线不变。服务端新增“私有记忆概览”与“Agent 自有私有记忆读取”两类接口，Web 只接入去敏概览与候选提交状态，不直接拉取或展示任意 Agent 的私有原文。私有原文读取仍然要求 `agentId` 命名空间，并保持“私有记忆 -> 共享候选 -> 人工确认 -> 共享层”的单向提升路径。

**Tech Stack:** Node.js 22, npm workspaces, TypeScript, Fastify, React, Vite, Vitest, Testing Library, JSON file storage

---

## Scope Decision

本计划只做 `L3` 的最小受控工作面，不做“私有知识后台”。

进入本计划：

1. 私有记忆概览对象与 API
2. Agent 自有私有记忆列表读取能力
3. Web 右侧面板中的去敏私有记忆状态区
4. 从私有记忆提交共享候选的最小交互补强
5. 对“普通面板不暴露 L3 原文”的回归测试

不进入本计划：

1. 普通人类用户直接浏览任意 Agent 私有记忆全文
2. 私有记忆搜索、过滤器、标签管理器
3. embedding / semantic retrieval
4. 自动把私有记忆升格为共享知识
5. 多租户权限系统或登录系统

## Implementation Notes

1. 去敏概览优先展示数量、最后更新时间、待提交候选数量、最近来源房间，不展示 `body`
2. `GET /api/private-memories` 仍要求 `agentId`，不改变现有权限边界
3. 新增概览接口时，必须明确它返回的是 `summary/overview`，不是原始私有记忆
4. Web 端的“私有记忆状态”区只作为状态感知和工作入口，不承担原文浏览职责
5. 所有测试都必须显式证明“普通面板不暴露 L3 原文”

## Plan Review Notes

1. 这个阶段的关键不是“让人看到更多”，而是“在不泄露 L3 原文的前提下，建立私有记忆的工作面”
2. 如果执行过程中发现“需要直接看原文”才能达成目标，应拆出下一阶段的 Agent 专用面板，不要把当前公共面板越权扩展
3. 如果后续要做更强的 Agent 自有视图，优先走独立路由或独立会话入口，不把权限复杂度压进当前房间右栏
