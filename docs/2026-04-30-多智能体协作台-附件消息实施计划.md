# 多智能体协作台 附件消息 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把附件上传链路补成正式消息闭环，让上传后的文件直接进入房间时间线并以图片预览卡片或文件卡片显示。

**Architecture:** 继续沿用现有 `upload -> createMessage -> realtime render` 主链路，不新增独立附件事件；服务端在 canonical message pipeline 内绑定附件与 `messageId`，前端基于统一时间线模型渲染文本与附件。

**Tech Stack:** Node.js 22, npm workspaces, TypeScript, Fastify, React, Vite, Vitest, Testing Library, Zod

## Scope Decision

本计划只覆盖“上传即发正式附件消息”：

1. 扩展附件与消息协议
2. 扩展 `/api/messages` 支持纯附件消息
3. Web 上传后立即发送正式附件消息
4. 时间线渲染图片预览卡片与文件卡片

以下内容明确不进入本计划：

1. 待发送附件队列
2. 多附件拖拽与批量管理
3. 图片灯箱
4. 权限签名 URL
5. 摘要理解附件内容

## Implementation Notes

1. 不新建附件专用消息事件类型，仍然使用 `message.created`。
2. `body` 允许为空字符串，但接口必须保证“正文或附件至少一个存在”。
3. `uploadFile()` 返回附件草稿；真正绑定 `messageId` 的动作只在 `createMessage()` 内完成。
4. 时间线渲染必须兼容“只有正文”“只有附件”“正文 + 附件”三种形态。
5. 图片预览直接使用附件 URL，不引入缩略图服务。
