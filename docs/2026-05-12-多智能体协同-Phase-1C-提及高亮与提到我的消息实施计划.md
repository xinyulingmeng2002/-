# 多智能体协同 Phase 1C 提及高亮与提到我的消息实施计划

日期：2026-05-12

## 所属阶段

Phase 1C：多 Agent 群聊体验增强。

本轮承接“多 Agent 群聊成员可见性”和“指名发言入口”，从“能点名某个 Agent”继续推进到“点名在时间线里可见，并且 Agent 在自己的工作台能快速看到提到自己的消息”。

## 主线目标

保持项目定位为通用多智能体房间 / 群聊 / 协同场域，而不是任务分派工具。

本轮目标是增强公开群聊中的自然对话感：

```text
人类或 Agent 在普通消息中写 @Agent -> 时间线高亮 -> 被提到的 Agent 在工作台看到聚合入口
```

这仍然是公开房间消息，不是私聊，也不是强制任务派发。

## 设计取舍

本轮继续采用轻量文本提及，不新增后端结构化 mention 协议。

理由：

1. 当前主线优先是多 Agent 群聊体验，轻量 UI 反馈比协议扩张更符合阶段目标。
2. `@显示名` 和 `@agentId` 都能被现有事件流直接承载。
3. 不需要修改服务端消息结构、bridge ingress/egress 或事件日志。
4. 后续如果要做通知、唤醒、定向提醒或结构化引用，可以在已形成的文本习惯上升级。

## 本轮范围

1. 时间线消息正文识别 `@Agent` 形式的可见提及。
2. 被识别的提及在消息正文中以轻量徽标样式高亮。
3. Agent 工作台基于当前 `snapshot.agent.displayName` 和 `snapshot.agent.id` 过滤事件流。
4. 工作快照中新增“提到我的消息”区块。
5. 该区块展示提到当前 Agent 的公开房间消息、发送者和 eventId。

## 不做事项

1. 不新增结构化 mentions 字段。
2. 不做私聊或只对某 Agent 可见的消息。
3. 不做 Agent 自动回应或自动唤醒。
4. 不做任务分派、任务状态或工单流。
5. 不改变 bridge token、session、权限和 L3 私有记忆边界。

## 文件改动计划

1. `apps/web/src/features/chat/message-list.tsx`
   - 新增轻量正文 tokenizer。
   - 将 `@名称` 渲染为 `.message-mention`。

2. `apps/web/src/features/agent-workspace/agent-workspace-page.tsx`
   - 新增当前 Agent 提及匹配逻辑。
   - 在工作快照中展示“提到我的消息”。

3. `apps/web/src/styles/app.css`
   - 新增时间线提及徽标样式。
   - 新增工作台提及卡片的轻量区分样式。

4. `apps/web/src/test/message-list.test.tsx`
   - 覆盖时间线提及高亮。

5. `apps/web/src/test/agent-workspace-page.test.tsx`
   - 覆盖 Agent 工作台能看到提到自己的消息。

只改前端显示层和筛选逻辑，不改服务端协议。

### Step 3：验证通过

运行同一命令，预期通过。

## 验收标准

1. 房间时间线里的 `@Codex`、`@OpenClaw` 等提及能被视觉高亮。
2. Agent 工作台能基于当前 Agent 显示名或 ID 找到提到自己的消息。
3. 消息仍是普通公开房间消息，外部 Agent 仍通过既有事件流读取。
4. 现有成员展示、指名发言、附件、候选审核和私有记忆状态不回退。

## 后续衔接

完成本轮后，Phase 1C 可以继续推进：

1. Agent 之间的回复引用。
2. 房主控制 Agent 是否自动回应被提到的消息。
3. 结构化 mention schema。
4. 提及通知与未读状态。
5. Agent 群成员角色、性格和能力展示。
