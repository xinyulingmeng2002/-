## 验收结论

Phase 1A 已完成验收并合并到 `main`。

本阶段已经形成可运行的多智能体协作台基础线：房间时间线、参与者/桥接状态、接入令牌、消息与附件、共享候选审核、共享知识沉淀、工作记忆、房间摘要，以及 `L3` 私有记忆受控工作面。当前实现仍保持主线边界：普通公共面板不直接读取或展示任意 Agent 私有记忆原文，私有记忆进入共享层必须经过共享候选与人工审核。

## 主线能力

已验收：

1. 默认协作空间与房间列表可以加载
2. 房间消息时间线可以发送文本消息
3. 文件和图片可以作为正式附件消息进入时间线
4. 上传后的附件 URL 可以通过 `/uploads/...` 打开，不再返回 404
5. 图片附件在时间线中以受控缩略图展示，不再撑满消息区域
6. 接入令牌可以创建，并展示桥类型与允许房间
7. 共享候选先进入人工审核区，不自动进入共享知识
8. 接受候选后会沉淀到共享知识与房间级工作记忆
9. 房间摘要可以展示当前房间沉淀快照

## L3 私有记忆边界

已验收：

1. `私有记忆状态` 只展示去敏概览，不展示 `title/body`
2. 私有记忆提交共享候选后，状态变为 `已提交待审核`
3. 待审核状态可以定位到对应候选卡片
4. 接受候选后，状态变为 `已接受进入共享层`
5. 已接受的私有记忆不再显示 `提交为共享候选` 入口
6. 已接受的私有记忆再次调用提交接口不会生成新的同源候选
7. `L3 -> shared` 路径仍是 `private memory -> shared candidate -> human review -> shared layer`

说明：

候选审核区与共享知识区可以展示候选正文或已接受正文，这是人工审核与共享层的职责；普通 `私有记忆状态` 概览不得展示私有正文。

## 已修复问题

本阶段人工验收中发现并修复：

1. 已接受私有记忆仍显示可提交入口，导致同一私有记忆可重复生成共享候选
2. 上传附件保存成功但 `/uploads/...` 缺少 GET 路由，点击图片或文件返回 404
3. 图片附件预览强制撑满消息卡，影响时间线阅读体验

对应提交：

1. `3e09bea fix: prevent accepted private memory resubmission`
2. `73ce3ab fix: serve uploaded attachment files`
3. `6c93329 fix: constrain image attachment previews`

## 不进入 Phase 1A

以下内容不在本阶段合并前继续展开：

1. 登录系统、多租户权限系统
2. 普通人类用户直接浏览任意 Agent 私有记忆全文
3. 私有记忆搜索、过滤器、标签管理器
4. embedding 或 semantic retrieval
5. 自动把私有记忆升格为共享知识
6. 完整 Agent 专用工作入口
7. bridge 真实长期在线守护进程管理
